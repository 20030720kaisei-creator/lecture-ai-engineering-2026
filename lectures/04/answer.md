# 第4回 解答

## 演習

- 基準別の一致率（直す前）：根拠 6/10、範囲 9/10、ヒント 10/10、分かりやすさ 9/10、回の表示 9/10
- 要確認の件数（直す前）：0件
- 直した基準と、書き足した方針：分かりやすさについては「内容や役割の適切さ」を他の基準に持ち込まないこと、また「同じ説明の言い換えや冗長な繰り返し」は読みやすさの観点で不合格とする方針を追記した。これにより、項目ごとに基準を独立に見て評価する意識を明確にした。
- 基準別の一致率と要確認の件数（直した後）：根拠 6/10、範囲 9/10、ヒント 10/10、分かりやすさ 9/10、回の表示 9/10、要確認 0件
- 講師のラベルと自分のラベルで判定が違った項目と、そう判定した理由：特に「回の表示」と「分かりやすさ」が主観的で、講師のラベルとズレやすかった。たとえば、#04 は「同じ説明を繰り返している」のが分かりやすさの観点で不自然なので fail とした。逆に、#06 のように「答えの正しさ」そのものは他基準で判定し、読みやすさだけで評価すべきものは別に分けるべきだと判断した。
- 気づき・疑問：LLM の採点は、基準の文言が曖昧だと自分の基準とズレやすく、特に主観的な「分かりやすさ」は人間でも割れやすいことが分かった。要確認を減らしたり、基準を明文化することで、採点器の再現性が上がるのが実感できた。今回は要確認 0 件だったが、基準が曖昧なままだと LLM が自分で補完して pass/fail を決めてしまう可能性があるため、評価設計は「どこを曖昧に残すか」を決める作業だと感じた。

## 宿題

- 取り組んだレベル：基礎
- やったこと：採点のモデルを `gemini-3.5-flash-lite`（既定）から `gemini-3.5-flash` に切り替えて、同じ `lectures/04/labels.jsonl` を使って `uv run python -m app.judge` を再実行した。比較対象は第4回の演習で使った既定の採点結果とした。
- 結果：既定モデルでは、根拠 6/10、範囲 9/10、ヒント 10/10、分かりやすさ 9/10、回の表示 9/10、要確認 0件。`gemini-3.5-flash` に変えた場合は、根拠 8/10、範囲 9/10、ヒント 10/10、分かりやすさ 9/10、回の表示 9/10、要確認 0件。総合一致率は 7/10 のままだが、根拠の一致率だけ 2 点改善した。特に #03 の「LoRA の用語解釈」を正しく合格に判定できるようになり、誤判定が減った。
- 気づき・疑問：モデルの違いで同じ基準でも途中までの判定が変わることがあるため、LLM の評価器は「スコアそのもの」よりも「どの基準でズレやすいか」を見るほうが大事だと感じた。今回の違いは主に根拠の厳密さに出ており、分かりやすさや範囲はほぼ変わらなかった。採点器を信頼する前に、少しのモデル変更でも一致率が変わることがあるので、評価セットと基準の明文化が重要だと分かった。
